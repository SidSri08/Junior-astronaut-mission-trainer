# Activation Order

This is a recommended session-opening order, not evidence that any session or agent has been started.

## Phase 1 — Organization bootstrap
1. Human owner confirms repository, branch, schedule and MVP priorities.
2. Open A3 Chief Orchestrator prompt and provide project context, repository inventory and decision authority.
3. A3 opens/requests six Department Lead readiness reports (A1, B1, C1, D1, E1, F1). If true sub-agent launch is unavailable, the human opens six independent sessions.
4. Leads confirm specialist availability, model/tool capability and departmental risks. Do not open all 24 specialist sessions by default.

## Phase 2 — Architecture and evidence baseline
5. Activate A-S1, A-S2 and A-S3 for architecture/game loop/contracts; A-S4 performs a separate audit after initial decisions.
6. Activate D-S1, D-S2 and D-S3 for distinct lunar science topics; D-S4 consolidates source/claim validation. Parallelize research topics only.
7. Activate E-S1 and E-S2 for learning goals and source-grounded science language; E-S4 drafts tutorial/UX copy after controls are known.
8. A1 and D1 submit departmental approvals. A3 coordinates human approval of state model, scope, contract and source policy.

## Phase 3 — MVP implementation
9. Activate B-S1 scene, B-S2 assets, B-S3 UI and B-S4 bootstrap according to frozen contracts. They may work in parallel only on disjoint owned paths.
10. Activate C-S1 shared state/resource systems, C-S2 mission events, C-S3 exactly two minigames and C-S4 balance data. C-S1 must publish state contracts before dependent tasks begin.
11. Activate E-S3 technical documentation only after setup commands and architecture are stable; it may prepare a clearly labeled draft earlier.

## Phase 4 — Independent QA and release
12. F-S1 creates and runs functional tests; F-S2 audits code; F-S3 measures performance; F-S4 stress-tests mechanics. F1 consolidates evidence and maintains the bug log.
13. Implementation owners fix defects; QA retests. Do not let a fix author mark their own change accepted without independent verification.
14. A3 performs integration review, obtains QA recommendation, and prepares human release decision.
15. Human owner rehearses demo and approves, conditionally approves or rejects release.

## Just-in-time specialist activation
Activate a specialist only when inputs, ownership, dependencies and acceptance criteria are ready. A role prompt may be reused for a later task; create a new Task ID rather than duplicating the role or launching a recursive team.
